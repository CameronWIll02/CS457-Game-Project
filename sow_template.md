### 1.1 Game Overview
- **Chosen Game:** Gen 1 Pokémon Battle Simulator (custom turn-based battler)
- **Player Capacity:** 2 Players (Simulated via 2 CML Client nodes)
- **Game Summary:** A battle-only simulator based on Generation 1 Pokémon mechanics, scoped down for a single-semester build. Each player fields a fixed roster (e.g., 6 Pokémon) drawn from a curated pool of roughly 15–20 Gen 1 species. Every Pokémon is set to a fixed level (e.g., Level 50), so only base stats are used — no stat experience, EVs, or DVs to calculate. Each Pokémon has a small curated moveset (2–4 moves) covering the core Gen 1 type chart, and there are no held items (consistent with Gen 1). Each round, both players choose a move for their active Pokémon; damage is resolved with a simplified version of the Gen 1 damage formula (base stats, move power, and type effectiveness). Status conditions (e.g., burn, paralysis) may be added later as a stretch goal but are not required for the core implementation.

### 1.2 Core Game Rules & Win/Draw Conditions
- **Turn Mechanics:** Each round, both players submit a move for their active Pokémon before either move is resolved. The Pokémon with the higher effective Speed stat acts first; if Speeds are equal, Player 1 acts first. If a Pokémon faints during a round, its player must choose a replacement from their remaining team before the next round begins.
- **Victory Condition:** A player wins when every Pokémon on the opposing player's team has fainted (HP reduced to 0).
- **Draw/Tie Condition:** If neither team has been fully defeated after a fixed maximum number of rounds (e.g., 50), the match is declared a draw.

### 2.2 Message Schema Definitions

#### Message Types:
1. `CONNECT` (Client -> Server): Request to join the game room.
2. `LOBBY_WAIT` (Server -> Client): Notification that server is waiting for Player 2.
3. `GAME_START` (Server -> Clients): Game initiated, assigns roles (e.g. Player X vs Player O).
4. `MOVE` (Client -> Server): Player action (e.g., cell coordinates or answer choice).
5. `STATE_UPDATE` (Server -> Clients): Broadcast current game board / state and active player turn.
6. `GAME_OVER` (Server -> Clients): Victory / Draw notification with final scores.
7. `ERROR` (Server -> Client): Invalid move or malformed packet error.

#### Example JSON Protocol Schema:
```json
{
  "msg_type": "MOVE",
  "player_id": "Player_1",
  "payload": {
    "row": 0,

  },
  "timestamp": 1727000000
}
```
